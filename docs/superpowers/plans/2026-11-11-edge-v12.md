# V1.2 Edge extension implementation plan

Goal: extend the existing desktop application with a current-post-only Edge draft panel, opt-in automatic natural replies, safe session caching and a Native Messaging companion. The user explicitly requested implementation, testing and packaging, so proceed without an additional design approval round.

Architecture: MV3 content script (visible current post + isolated panel) → service worker (origin checks, settings, cache, request ownership) → Native Messaging host (existing QtNetwork DeepSeekClient + prompts + CredentialStore). No localhost listener. Keep all desktop code and its current uncommitted source-panel features intact.

Alternatives: localhost requires a listening service, per-install authentication and CORS management; Native Messaging provides an Edge extension allowlist and process lifetime linked to the browser. Choose Native Messaging. A public manifest key fixes the unpacked extension ID; it is not a secret.

Platform boundary: X automation rules disallow non-API website scripting and do not explicitly exempt DOM reply insertion. Following the user's requested fallback, do not write to, click, submit or synthesize events in X's composer. Provide a clearly labelled manual-fill/copy action with Ctrl+V instructions. Current rendered-post inspection is minimal, on the foreground detail page only, without background crawling, hidden APIs, cookies or remote fetching; do not claim official X authorization. Provide manual source input when extraction is uncertain.

Preservation: pre-existing 158 source files captured in `work/edge-v12-preserve/source-before-v12.zip` outside the repository; baseline hashes and diff saved. No branch switch, reset, clean, automatic commit of pre-existing changes or overwrite of old EXEs.

## Shared interface

- Extension ID: `pibjjmjbipbifeddoahjagcinihkcgnf`.
- Host: `com.suishou.reply`; exact origin `chrome-extension://pibjjmjbipbifeddoahjagcinihkcgnf/`.
- Version: extension and native bridge `1.2.0`; desktop remains its existing version.
- Native JSON frame: UTF-8, 4-byte little-endian length, inbound maximum 32768 bytes, outbound maximum 65536 bytes.
- Generate: `{v:1,type:"generate",id:string,post:{id:string,url:string,author:string,text:string},style:"自然"|"犀利"|"幽默",previous:string}`. IDs limited to `[A-Za-z0-9_-]{1,80}`; post ID digits 1–25; canonical URL `https://x.com/<handle>/status/<id>` (twitter.com accepted and canonicalized at browser boundary), author `@handle`, text 1–3000 nonempty characters, previous ≤500 characters. Reject extra fields, unsafe Unicode and invalid URL/ID/author relationships.
- Cancel: `{v:1,type:"cancel",id:string}`; ping `{v:1,type:"ping",id:string}`.
- Result: `{v:1,type:"result",id:string,text:string,usage:object}`; error `{v:1,type:"error",id:string,code:string,message:string}`; canceled `{v:1,type:"cancelled",id:string}`; ready `{v:1,type:"ready",id:string,version:"1.2.0"}`.
- Native host never takes keys, model names, arbitrary endpoints, prompt overrides or file paths from messages. Existing settings supply model. Credentials read only when generating.
- Native process one active request, timeout via existing transport; stdin EOF / idle deadline cancels and exits; no automatic network retry. No source text or keys logged.

## Review focus

1. Current URL changes before React removes the old article: never reuse prior post or display old request results.
2. Current article contains quoted tweets, replies or multiple links: exact own timestamp permalink and own text only; ambiguity falls back to manual input.
3. User edits during a request / switches style / returns to an earlier post: edited draft survives, stale results cannot overwrite it.
4. Browser closes, hides, switches tab, disables auto or navigates: cancel pending work; no timers reconnect and retry paid work.
5. Content scripts cannot smuggle endpoints or keys through native messages; cache is session-only and no remote content is rendered as HTML.
